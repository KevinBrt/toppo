# Dépannage

Commencez par les journaux : `docker compose logs toppo` dit ce que Toppo a fait et, quand il échoue, pourquoi.

| Ce qui se passe                                         | Ce qu’il faut faire                                                                                                                                                                                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Le code d’installation est perdu                        | Redémarrez Toppo (`docker compose restart toppo`) : il en affiche un nouveau tant que l’installation n’est pas faite.                                                                                                                |
| Toppo ne démarre pas                                    | Les journaux disent pourquoi : une variable `TOPPO_*` inconnue ou invalide, une base de données injoignable, une migration qui a échoué (la base reste alors telle qu’elle était).                                                   |
| `/health` répond 503                                    | Toppo tourne mais n’atteint pas sa base de données : vérifiez `docker compose ps` et les journaux de `db`.                                                                                                                           |
| Les liens des e-mails pointent vers la mauvaise adresse | Définissez `TOPPO_URL` sur l’adresse que les gens ouvrent, puis `docker compose up -d`.                                                                                                                                              |
| Aucun e-mail n’arrive                                   | Envoyez un message de test depuis **Paramètres › E-mail** : il dit ce qui n’a pas marché, la connexion, TLS, le compte ou le message refusé. Regardez les spams, et vérifiez que l’adresse d’expédition peut envoyer par ce serveur. |
| Tout le monde a été déconnecté après un déménagement    | Le volume `/data`, avec sa clé secrète, n’a pas suivi : restaurez-le, ou définissez vous-même `TOPPO_SECRET`. Saisissez de nouveau le mot de passe de l’e-mail dans **Paramètres › E-mail**.                                         |
| Les pièces jointes échouent derrière le proxy           | Le proxy refuse les grosses requêtes : faites-lui accepter la taille de `TOPPO_ATTACHMENT_MAX_SIZE_MB` (nginx : `client_max_body_size`).                                                                                             |
| Les connexions sont refusées pour excès de tentatives   | Derrière un reverse proxy, Toppo voit chaque client à l’adresse du proxy tant que `TOPPO_TRUST_PROXY=true` n’est pas défini ([l’adresse du client](./reverse-proxy#l-adresse-du-client)).                                            |
| L’interface parle la mauvaise langue                    | Chaque personne choisit la sienne dans **Mon compte › Langue** ; les e-mails la suivent.                                                                                                                                             |

Toujours bloqué ? Ouvrez une [issue](https://github.com/KevinBrt/toppo/issues) avec la version (en bas de la barre latérale) et ce que disent les journaux. Un problème de sécurité se signale en privé, comme l’explique [SECURITY.md](https://github.com/KevinBrt/toppo/blob/main/SECURITY.md).
